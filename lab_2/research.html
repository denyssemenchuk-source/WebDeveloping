4.1. Дослідження CSS Box Model

Computed Size Analysis

Завдання: Створити два блоки <div> з однаковими width: 260px та height: 140px. Одному задати box-sizing: content-box, іншому — border-box. Додати padding: 24px та border: 8px.

1. content-box (W3C Default)

content-box (260x140)

Фактичний розмір на екрані: 324px × 204px

Формула: Total Width = width (260) + padding-left/right (48) + border-left/right (16) = 324px.

2. border-box (Modern Standard)

border-box (260x140)

Фактичний розмір на екрані: 260px × 140px

Формула: Content Box = width (260) - padding (48) - border (16) = 196px × 76px.

Висновок: При використанні box-sizing: border-box розмір елемента чітко відповідає зазначеним у властивостях width та height, що унеможливлює розпирання сіток та спрощує розрахунки при адаптивній верстці.

4.2. Дослідження каскаду (The Cascade)

Source Order & Origin

Завдання: Задати колір тексту для одного елемента трьома способами з однаковою специфічністю, але в різному порядку.

Тестовий блок: .color-rule-a (Blue) + .color-rule-b (Red)

Спостереження: Текст відображається червоним кольором (правило .color-rule-b), тому що воно розміщене в CSS файлі нижче за .color-rule-a.

Висновок: Порядок перерахування класів в HTML-атрибуті (наприклад, class="color-rule-b color-rule-a") НЕ має значення. За однакової специфічності завжди перемагає правило, яке описане ПІЗНІШЕ у каскаді (Source Order).

4.3. Дослідження специфічності (Specificity)

ID vs Class Chains

Завдання: Порівняти селектори тегу, класів та ID, спробувати перебити ID ланцюжком класів.

#specificity-target-id завжди перемагає
СелекторСпецифічність (Inline, ID, Class, Element)Пріоритет
div(0, 0, 0, 1)Найнижчий
div.specificity-demo-item(0, 0, 1, 1)Низький
.c1.c2.c3.c4.c5.c6.c7.c8.c9.c10(0, 0, 10, 0)Середній

4.4. Дослідження успадкування (Inheritance)

Inherited vs Non-Inherited

Завдання: Задати font-family та color для батьківського контейнера, розмістити всередині <p>, <a> та <button>.

Параграф: Успадкував фіолетовий колір і шрифт Courier New автоматично.

Посилання за замовчуванням (User Agent блокує color)
Посилання з color: inherit (успадковано)

Висновок: Більшість властивостей типографіки (color, font-family, line-height) успадковуються дочірніми текстовими елементами. Проте теги форми (<button>, <input>) та посилання (<a>) мають специфічні стилі браузера за замовчуванням (User Agent Stylesheet), які вимагають явного застосування ключового слова inherit для збереження єдиного стилю.

4.5. Дослідження CSS Custom Properties (Variables)

Scoping

Завдання: Оголосити змінні в :root, перевизначити локально всередині класу .card--dark.

Глобальний токен :root

Використовує значення за замовчуванням зі світлої або активної глобальної теми.

Локальний токен .card--dark

Перевизначено фон та колір тексту лише для цієї підгілки DOM дерева.

Висновок: CSS-змінні підкоряються каскаду та успадкуванню. Локальне перевизначення змінної в селекторі компонента діє на сам елемент і всіх його нащадків, дозволяючи створювати незалежні теми компонентів без створення надлишкових селекторів.

4.6. Повторне використання стилів і компонентний рефакторинг

DRY Design System

Запитання: Чому компонентний підхід кращий за написання унікальних стилів для кожного окремого елемента?

Переваги компонентного підходу (DRY): 1. Зменшення розміру файлу стилів (CSS bundle size) за рахунок усунення дублювання. 2. Легкість підтримки: зміна відступу чи радіуса кнопки в класі .btn оновлює всі кнопки у проєкті. 3. Консистентність дизайну: єдиний візуальний ритм та передбачувана поведінка інтерфейсу. 4. Низька специфічність: використання простих класів (.btn, .btn--primary) запобігає «війнам специфічності».
