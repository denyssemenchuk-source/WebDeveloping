## 2. Дослідницькі завдання та експерименти (Розділ 4)

### 4.1. Box Model (Модель візуального форматування)
- **Експеримент:** Створено два блоки `<div>` з однаковими розмірами `width: 260px; height: 140px; padding: 24px; border: 8px solid ...`.
- **Порівняння властивостей:**
  1. `box-sizing: content-box` (стандарт W3C за замовчуванням):
     - Розрахунок ширини: $260\text{px} + (24\text{px} \times 2) + (8\text{px} \times 2) = 324\text{px}$.
     - Розрахунок висоти: $140\text{px} + (24\text{px} \times 2) + (8\text{px} \times 2) = 204\text{px}$.
     - Фактичний зайнятий простір на екрані: **324 × 204 px**.
  2. `box-sizing: border-box` (сучасний стандарт):
     - Загальна ширина фіксована: **260 px**.
     - Загальна висота фіксована: **140 px**.
     - Внутрішній розмір контенту (Content Box) автоматично зменшується: $260 - 48 - 16 = 196\text{px}$, а висота: $140 - 48 - 16 = 76\text{px}$.
- **Висновки:** `box-sizing: border-box` є найбільш передбачуваним підходом, оскільки зміна padding або border не ламає сітку і не призводить до горизонтального скролу чи випадання елементів із батьківських контейнерів.

### 4.2. Cascade (Каскад та порядок правил)
- **Експеримент:** Елементу присвоєно класи `.color-rule-a` (синій) та `.color-rule-b` (червоний) з однаковою специфічністю `(0, 1, 0)`.
- **Спостереження:**
  - Зміна порядку класів в HTML: `<div class="color-rule-b color-rule-a">` не змінює колір.
  - Колір тексту завжди червоний, оскільки в файлі `styles.css` правило `.color-rule-b` розташоване нижче за `.color-rule-a`.
- **Висновки:** За однакової специфічності селекторів та однакового джерела походження (Origin) вирішальним фактором є порядок появи правила в коді (Source Order Rule — останнє оголошене правило перемагає).

### 4.3. Specificity (Специфічність)
- **Експеримент:** Порівняно пріоритет селектора тегу `div` (0,0,1), комбінатора `div.class` (0,1,1), ланцюжка з 10 класів `.c1.c2...c10` (0,10,0) та селектора ID `#specificity-target-id` (1,0,0).
- **Калькуляція ваги селекторів:**

| Селектор | Inline | ID (A) | Class/Attr (B) | Element (C) | Результат |
|---|---|---|---|---|---|
| `div` | 0 | 0 | 0 | 1 | Перебито |
| `div.specificity-demo-item` | 0 | 0 | 1 | 1 | Перебито |
| `.spec-c1.spec-c2... (10 класів)` | 0 | 0 | 10 | 0 | Перебито |
| `#specificity-target-id` | 0 | **1** | 0 | 0 | **ПЕРЕМАГАЄ** |

- **Висновки:** Розряди специфічності мають сувору ієрархію без переносу розрядів (тобто 100 класів не можуть перетворитися на 1 ID). Селектор ID завжди сильніший за будь-яку кількість класів.

### 4.4. Inheritance (Успадкування)
- **Експеримент:** Батьківському блоку задано `font-family: 'Courier New'` та `color: #9333ea`.
- **Спостереження:**
  - Тег `<p>` автоматично успадкував колір та шрифт.
  - Тег `<a>` успадкував шрифт, але колір залишився синім через стиль браузера (User Agent stylesheet: `color: -webkit-link`).
  - Тег `<button>` не успадкував ні шрифт, ні колір через дефолтні стилі браузера для кнопок (`font: -webkit-small-control`, системні кольори).
- **Рішення:** Застосування `font-family: inherit` та `color: inherit` нормалізує елементи та усуває конфлікти зі стилями платформи.

### 4.5. CSS Custom Properties (Variables)
- **Експеримент:** У `:root` винесено палітру кольорів, шрифти, радіуси та відступи. У класі `.card--dark` локально перевизначено `--card-bg` та `--card-text`.
- **Висновки:** CSS-змінні мають область видимості (scope), що наслідується вниз по DOM-дереву. Це дозволяє створювати автономні теми та варіанти компонентів без дублювання складної логіки селекторів.

### 4.6. Повторне використання стилів (DRY-рефакторинг)
- Виділено спільну структуру кнопок (`.btn`) з варіантами модифікаторів (`.btn--primary`, `.btn--secondary`, `.btn--outline`, `.btn--sm`, `.btn--lg`).
- **Переваги компонентного підходу:**
  1. Скорочення розміру файлу стилів на 60–80%.
  2. Єдина точка правки для підтримки дизайн-системи.
  3. Відсутність потреби у використанні `!important`.

## 3. Практична частина (Розділ 5)

У проєкті реалізовано повноцінну адаптивну вебсторінку та інтерактивну лабораторію:
1. **Глобальний Box-sizing:** встановлено `*, *::before, *::after { box-sizing: border-box; }`.
2. **CSS Variables у `:root`:** кольори, відступи (`--space-*`), типографіка (`--font-*`), тіні (`--shadow-*`), підтримка світлої та темної тем (`[data-theme='dark']`).
3. **Модульні компоненти:** `.navbar`, `.hero`, `.card`, `.card--dark`, `.card--accent`, `.badge`, `.btn`, `.grid`.
4. **Інтерактивні експерименти:** динамічний повзунок зміни відступів для Box Model, перемикач порядку правил для Cascade, перемикач теми інтерфейсу.

## 4. Відповіді на питання до усного захисту (Розділ 7)

1. **Чому цей елемент має саме такий фізичний розмір?**
   - Завдяки `box-sizing: border-box` ширина елемента (наприклад, 260px) включає в себе `padding` (24px + 24px) та `border` (8px + 8px). Внутрішній контентний блок автоматично стискається до $260 - 48 - 16 = 196\text{px}$.
2. **Яке правило в DevTools було перекреслене і чому?**
   - У випадку каскаду для одного елемента з двома класами однакової ваги перекреслюється правило, яке оголошено раніше у файлі CSS, оскільки перемагає правило, що йде пізніше у вихідному коді (Source Order).
3. **Чому текстовий елемент отримав такий шрифт, хоча йому він не задавався?**
   - Властивість `font-family` є спадковою (inherited property). Браузер перевіряє батьківські елементи аж до `body` / `html` і застосовує знайдений шрифт.
4. **Навіщо використана CSS Variable? Що буде, якщо змінити її значення в `:root`?**
   - CSS-змінні забезпечують централізований контроль дизайн-системи. Зміна значення змінної в `:root` автоматично оновлює всі елементи сторінки, що на неї посилаються, у реальному часі без перезавантаження.
5. **Приклад винесення стилів у спільний клас. Як би виглядав код без нього?**
   - Клас `.btn` містить базові стилі (display, align-items, font-family, padding, border-radius, transition, cursor). Без нього кожен тип кнопки вимагав би повного копіювання цих 10+ рядків коду у кожен унікальний ID чи селектор.
