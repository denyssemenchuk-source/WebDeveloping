4.3. HTML <head> та метадані сторінки
Опрацювати:

MDN — Web page metadata
Google Search Central — Meta tags and attributes
Google Search Central — Influencing title links in Google Search
Дослідити:

Для чого потрібен <title>?
Для чого використовується <meta name="description">?
Чим відрізняються charset, viewport, robots та інші метадані?
Які метадані можуть впливати на те, як сторінка представлена в результатах пошуку?
Чому title та meta description повинні відповідати фактичному змісту сторінки?
Дослідіть, чи використовується Google метатег keywords, і зробіть висновок щодо доцільності його використання.
Практичний мініексперимент. Порівняйте два варіанти <head>:

<title>Pricing</title>
<meta name="description" content="Pricing page">

<title>SaaS Pricing Plans - Basic, Pro and Enterprise</title>
<meta name="description" content="Compare Basic, Pro and Enterprise SaaS pricing plans and choose a plan for your team.">

Поясніть, який варіант дає більше інформації користувачу та пошуковій системі і чому.

5. Практична частина: AI-assisted оптимізація вебсторінки на основі ЛР №2

Основна візуальна концепція та стилізація сторінки з ЛР №2 повинні бути збережені, а зміни цієї роботи мають стосуватися насамперед HTML-структури, метаданих, контенту та семантики.

5.1. Семантична структура сторінки
Доповнити існуючу сторінку структурними елементами header, nav, main та footer.
У main організувати контент у логічні секції.
Використати семантичні елементи замість універсальних контейнерів там, де для цього є відповідна HTML-семантика.
Рекомендована структура:

<header>
  <nav>...</nav>
</header>

<main>
  <section>...</section>
  <section>...</section>
</main>

<footer>...</footer>

5.2. Заголовки та структура контенту
Сформувати логічну ієрархію заголовків сторінки. Орієнтовна структура:

H1 - основна тема сторінки
H2 - тарифні плани
H3 - Basic
H3 - Pro
H3 - Enterprise

Текст, який був у ЛР №2, за необхідності переформулювати так, щоб він описував зміст сторінки, а не лише візуальний макет.

5.3. Оптимізація <head>
Додати та коректно налаштувати мінімально необхідні метадані:

<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>...</title>
  <meta name="description" content="...">
  <link rel="canonical" href="...">
</head>

Елементи title та description повинні бути унікальними, конкретними та відповідати фактичному змісту сторінки.

5.4. Оптимізація текстового контенту
Переглянути h1, заголовок секції pricing, короткий опис, назви та описи тарифів, тексти кнопок/посилань.
Забезпечити зрозумілість контенту для користувача та його відповідність основній темі сторінки.
Уникати штучного повторення ключових слів та keyword stuffing.
За потреби переробити тексти кнопок або посилань так, щоб вони описували дію чи призначення переходу.
5.5. Посилання та інтерактивні елементи
Проаналізувати кнопки з ЛР №2. Визначити, які елементи за своєю функцією повинні бути посиланнями, а які — справжніми кнопками.

<a href="...">...</a>
<button>...</button>

Наприклад, якщо елемент веде на іншу сторінку або секцію, він повинен бути посиланням, а не імітованою кнопкою. Текст посилання повинен бути зрозумілим без додаткового контексту.

5.6. AI-assisted оптимізація
Провести аудит вже існуючої реалізації ЛР №2 за допомогою AI-асистента. Не обмежуватися запитом на повне переписування HTML. Спочатку отримати аналіз та рекомендації, після чого самостійно прийняти рішення щодо їх реалізації.

мінімум 3 рекомендації AI;
перевірка рекомендацій за документацією;
реалізація обґрунтованих змін;
пояснення щонайменше 3 прийнятих або відхилених рекомендацій.
Вимоги до фінальної реалізації

Semantic HTML. Використано header, nav, main, section, article, footer там, де вони семантично доречні.
Heading hierarchy. Логічна структура h1 → h2 → h3 без використання heading лише заради стилізації.
Metadata. Коректно налаштовано lang, charset, viewport, змістовний title та meta description.
Content. Тексти відповідають змісту сторінки, є природними та не містять keyword stuffing.
Links and actions. a та button використані відповідно до їхнього призначення.
AI-assisted workflow. AI використано для аудиту/рефакторингу, а рішення щодо коду прийняті студентом.
